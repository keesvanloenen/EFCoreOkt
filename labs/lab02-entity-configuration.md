# Lab 02 - Entity Configuration

## Scenario

You'll create two new tables, configure them using both data annotations and fluent API, and load them up with sample data to display.  
Finally refactor the configuration into separate classes for each entity.

## Exercise 1: Configure Person model - Data Annotations

1. Check in the database the types of the columns in the `People` table. <div class="flavor-sqlserver">In SQL Server the two text columns are of type `nvarchar(MAX)`.</div><div class="flavor-pgsql">In PostgreSQL the two text columns are of type `text`.</div> This datatype is meant for large amounts of text. In this case we want to use a datatype that is fit for small amounts of text.
1. Update the table columns by using data annotations in the `Person` model:
   - **`Id`** is a primary key, autogenerated
   - **`FirstName`** has maximum length 50, not nullable
   - **`LastName`** has maximum length 50, not nullable
1. Compile and run the application. Check the fields in the database again. They should be OK now.

## Exercise 2: Add two models

1. Ensure next two tables are built and configured using Fluent API:
   - **Courses**
     - **`Id`**, `int`, primary key, **not generated by the database**
     - **`Title`**, maximum length 100, not nullable
     - **`Credits`**, `int`, not nullable
   - **Departments**
     - **`Id`**, `int`, primary key, autogenerated
     - **`Name`**, maximum length 50, not nullable
     - **`Budget`**, `decimal`, precision 8, scale 2 not nullable
     - **`StartDate`**, `date`, not nullable
     - <div class="flavor-pgsql">Make sure the tables are created in schema `school`.</div>
1. Compile and run the application. Check the database.\
   Hint: If there are no errors, but the 2 tables are not created, you'll need to add something to the DbContext.
